Permission Risks v32 实际关闭顺序、授权交付与费率结算

当前版本还检查终止后才出现的条件、限于管理员办理但由持有人授权的实际转账，以及最低费率非零时同额交易的实际费用。所有交易均保留来源、调用者和结算记录。

在已有 M1—M4 中，程序比较全局管理权的首次取得和后续使用，检查第三方实际可兑付权益、委托转移及其冻结，并区分通用额度与特权销毁。对部署时费率已经非零的资产，可通过管理员真实交易取得无费对照，并按相同请求核对总扣款、净额、额度和总发行量。每次比较保留原字节码、已提交效果和正常对照。首次占有管理权的发现以部署后确有可竞争的初始化窗口为适用条件。真实模型可用 behavior_questions 提议互相关联的入口，最终分类由程序核验。编译存档遗漏不可变值位置时，可以用 PRNEXT_IMMUTABLE_SOLC_DIR 指定可信本地编译器目录；完整创建字节码、运行字节码及元数据均与原档相同才采用补充结果。

新增的比较检查
图按源码声明、可达调用、状态写入和实际资产操作连接两个外部入口。M2 可在 behavior_questions 中提出哪两个操作值得比较，并标出各自的代码和可能的正常解释。M3 绑定可执行的具体问题，M4 在本地部署编译所得的原始字节码，从相同初态分别执行普通路线和可疑路线。已有静态分析和 Z3 检查继续工作。新比较检查涵盖取得并使用管理权、提前终止活动权益、重复获取可转让权益、按账户阻断转移，以及调参后实际扣减超过授权。报告中的 behavioral_comparisons 保存见证、环境、未观察到差异及无法执行的原因。

复现新增的字节码检查需在检测用 Python 环境中安装 configs/bytecode-requirements.txt 所列依赖。编译仍使用原项目编译环境。检查只对记录的编译目标、构造参数、交易和区块环境负责；未知外部合约代码、无法还原的构造环境和未能执行的反例会留下限制。执行不连接公链，不改写目标余额或存储。模型回答和图只发起问题，正式报警需要符合经批准的风险判据。

此目录包括 M1 静态程序分析与关系图、M2 有源码依据的 LLM 关系提案、M3 按 AC 或 FCR 生成风险检查、M4 程序及有界形式化核查。联合入口在 scripts/m03_entry.py。检测器接收源码编译产物及检测方向。作者的漏洞清单、工具的历史输出和计分程序位于检测器之外。

运行入口
在项目现有 Python 和编译环境中，从本目录执行：
  python scripts/m03_entry.py --route joint --help
已经编译的单元可使用：
  python scripts/m03_entry.py --route joint --root <材料根目录> --case <描述文件中的unit_id> --compiled-unit <描述文件绝对路径> --analysis-scope AC --fixture-response <保存的关系回答JSON> --out <新的报告目录>
FCR 检测使用 --analysis-scope FCR。复现本项目已批准的抽象账户口径时，环境变量 PR_NEXT_DESTROY_SCOPE 使用 abstract_account_ledger。已有的真实实验运行器还需绑定独立授权的 LLM 客户端、请求预算与账目。--fixture-response 只供离线诊断，报告会标记 diagnostic_only。源码包不含密钥或合约答案。

输入与产物
编译提取入口为 scripts/m03_extract_case.py，使用 solc 标准输入、与原合约匹配的编译器和版本生成程序与静态分析材料。联合入口读取 dataset-compiled-unit-v1 描述文件并校验产物摘要。输出包括 joint_report.json、阶段记录及 LLM 来源记录。本次本机验证使用 Python 3.12.14、crytic-compile 0.3.11、slither-analyzer 0.11.3、z3-solver 4.15.3.0。工程对照使用 solc 0.8.28，历史源码沿用各自原编译产物。

v27 主要改变
从权限建立、他人权益实际扣款及执行目标关系生成检查；M2 可提交由具体转账核查的权益关系；有界形式化判断区分毛扣与持有人有效授权、同一次交易内的连续委托、同一代理目标的运行代码与实际提交。金融调参证据单列；只有满足既定未授权权益销减条件才计入主 DESTROY。

继承的 v26 路径语义
1. 有状态的内部函数出现在布尔短路、条件表达式或取反中时，按执行到的分支保留写入、调用者、拒绝和返回。在可绑定的基类调用中按编译身份和继承顺序选择函数体。底层终止不会在内部返回后继续执行外围写入。
2. 代理边界核查把配置地址的写入与后续执行地址的路径相连。使用后状态、分离两次调用的参数和调用者，并将调用成功及外围路径条件送入验证。覆盖同一标量地址、局部别名和可以分析的修饰器。设定路径上的后续覆盖、消费路径上的固定地址要求或最终回滚，均能影响结论。
3. 对从储备中任意付款的既有 AC 检查，允许由请求者选择的布尔分支和经源码排查仅作直接常量写入的标记。仍核对资金入口、受控付款路径、付款对象、数额及是否扣减权益。有限分析中的符号状态、代理目标可能成功且不改变其他状态等假设不等同于链上攻击证明。

范围
仅在能绑定的源码路径内判断。索引决定的代理地址、任意汇编、未知第三方代码及复杂重入等情况仍可能无法完成核查。过去参与开发的材料、工程构造行为、离线保存回答应分别解释；本包本身不构成对独立项目的检出率证明。

v29 的共享待验操作清单在 m29_worklist.py 中实现。清单保留外部入口、提交路径、效果位置和精确存储对象。M3 用它发起授权建立、第三方余额处分、已入金权益收款人改写、调费结算以及冻结设置者的检查。共享状态本身不能推出授权。现有专门检查继续独立产生候选。
M2 仍提交带源码位置的关系；输入按声明索引写入者和读取者，并把具体效果与源码位置相连。M4 支持按 Solidity 声明解释常量映射键，对调费查询分别检查正常成交与超过额度的结算。分析受限、路径回滚和未能成立的授权前提须分开审阅。
离线诊断可在 analyze 的显式关键字参数中关闭新增跨操作检查组合或屏蔽语义提案；messages 可仅关闭提交给模型的任务子图。形式化前后的对照可按相同候选逐项检查，未验证项不能直接计作阳性。默认运行使用完整流程。
